How PocketDNA runs on one laptop

Plain-language walkthrough

Follow one episode through the machine

PocketDNA is one small app on your laptop, not a hosted service. Read the diagram left to right: your file enters the browser, a plain Node server runs the job, and a single door called the Muse adapter is the only way anything reaches Meta's models. The steps below say what each part does, what Muse contributes, and where Muse is deliberately kept out.

The critical view: what Muse is and is not trusted with

  • Muse never computes ancestry. The percentages come from deterministic math in your browser, or from the numbers you confirmed on a screenshot.
  • Muse never approves its own work. Whoever writes is never the one who checks, and every check is a separate call with a separate instruction.
  • Muse never decides geography. Map points come from dated records in a reference table, so a model cannot invent a route.
  • Everything Muse returns must fit a strict schema and is validated by code. Output that does not fit is retried once, then becomes a typed error. It is never shown raw.
  1. 1

    React app

    You
    Gets
    A screenshot or a raw 23andMe or AncestryDNA file that you drop on the page.
    Does
    Checks the file type and size, lets you correct extracted numbers, shows live progress, and plays the finished film.
    Hands over
    A screenshot goes to the server. A raw file goes to the in-browser worker and never to the server.
    Why you
    The page never holds a model key and never calls Meta itself. Keys exist only on the server.
    Guard
    Images up to 10 MB, raw files up to 50 MB, content sniffed rather than trusting the file name.
  2. 2

    Ancestry worker

    No model, runs in your browser
    Gets
    The raw genotype file, held in browser memory only.
    Does
    Parses and quality-checks the file, projects it onto the fixed PocketDNA PCA-25 space built from the reference datasets listed below, then fits Bronze Age, Medieval and Modern source mixes separately.
    Hands over
    A small derived summary (era shares, ranges, closest reference groups, limitations) goes to the app, then to the server as an EvidenceRecord. Genotypes and personal coordinates stay behind.
    Why no model
    Ancestry must be a repeatable measurement. A language model can write a convincing percentage that was never measured, so none is allowed near the numbers.
    Guard
    The server schema is strict: a genotype or coordinate field in the request is a 400 error and is never forwarded.
  3. 3

    Hono API and orchestrator

    No model, local server
    Gets
    A job request, then the EvidenceRecord (or the confirmed screenshot numbers).
    Does
    Starts the job, runs the agents in order, passes each agent's output to the next, enforces the audit gates, and streams progress to the page over server-sent events.
    Hands over
    Each agent receives exactly the typed data it needs. The finished film plan and image files are saved for the page to fetch.
    Why no model
    Muse models are the crew, not the producer. Ordering, budgets and approval gates are plain code so they behave the same every time and can be tested offline.
    Guard
    A paid-job rate limit, a run cost cap, and a kill switch that refuses every paid call.
  4. 4

    Muse adapter

    No model, the only door to Meta
    Gets
    A request from a pipeline stage: which agent, which model, which effort, the prompt file and the JSON schema the answer must obey.
    Does
    Checks the kill switch and the run cap, looks for a saved identical answer, calls Meta only on a miss, validates the reply, retries once with the error, then saves the answer and logs the cost.
    Hands over
    A validated, typed object back to the stage that asked, or a typed error.
    Why no model
    Putting every call through one module means cost, caching and validation cannot be skipped by accident in some corner of the code.
    Guard
    Per-run cap of $5, sha256 response cache, one cost-log row for every call.
  5. 5

    Muse Spark

    Muse Spark 1.3
    Gets
    A role prompt from the prompts folder plus the evidence or plan as JSON, or an image for the vision steps.
    Does
    Plays seven roles in turn: gatekeeper, extractor, interpreter, population profiler, director, narrative auditor and compliance auditor. The visual auditor is an eighth use, covered in the image diagram.
    Hands over
    Structured JSON that the adapter validates before anything uses it.
    Why Muse
    Only a model can read a messy screenshot, turn a table of percentages into grounded plain language, write a timed documentary script, and judge sentences against rules.
    Guard
    Cannot change a number, invent a source, infer traits, or approve its own output. Its work is checked by a different call.
  6. 6

    Muse Image

    Muse Image 1.0
    Gets
    A scene brief that code assembled from a cited record: place, date, purpose and strict style rules.
    Does
    Paints a 16:9 historical scene for a beat, and is asked to check period details with its own search before drawing. On a failed audit it edits the picture once.
    Hands over
    Picture bytes back through the adapter to the image step, where Spark audits them.
    Why Muse
    A specific place and century has no stock photo, and a documentary needs pictures. A generator can make them, as long as they are labelled as reconstruction.
    Guard
    Subjects are fictional inhabitants of a documented setting, never portraits of the viewer's ancestors. No text, battle, politics or maps in frame.
  7. 7

    Reel engine and globe

    No model, runs in your browser
    Gets
    The approved film plan and the approved image files.
    Does
    Draws every frame as a pure function of time, so the preview and an exported MP4 are identical. The globe uses reference coordinates only.
    Hands over
    The film you watch, with every claim linked to its source.
    Why no model
    Once the audits pass nothing creative should change. A model improvising at playback would break the guarantee that what was approved is what plays.
    Guard
    No claim is added after approval. Clicking a claim pauses the film and opens its citation.

Genomic datasets behind this step
