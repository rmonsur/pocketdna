Four kinds of actor, and what travels between them

The lanes are the point. The orchestrator schedules but writes nothing. The workers write but never judge. The auditors judge but never write. Deterministic code assembles but never invents. Each arrow carries a typed object, so a hand-off is a contract that code validates, not a chat message the next agent has to interpret.

The critical view: what Muse is and is not trusted with

  • Muse Spark appears in two lanes, as a writer and as a judge, but never in both roles on the same output. That separation is the main defence against a model approving its own mistake.
  • Only the orchestrator knows how much money has been spent. Each call is told the running total so the $5 cap holds across the entire job.
  • Where the diagram shows a loop, the loop is bounded: one script revision, one image repair per scene.
  1. 1

    Route and budget

    No model, orchestrator
    Gets
    The mode (screenshot or raw), the key, the cap and the kill switch.
    Does
    Chooses the road, stamps each call with the money spent so far, and decides what runs next from the previous result.
    Hands over
    Dispatches work to the Spark workers and passes each result forward.
    Why no model
    Control flow should be predictable and testable. Muse is the crew, not the producer.
    Guard
    Kill switch, per-run cap, rate limit on paid jobs.
  2. 2

    Gate and extract

    Muse Spark 1.3 · low, then medium
    Gets
    A screenshot.
    Does
    Gatekeeper decides accept or reject, extractor reads the numbers.
    Hands over
    Draft shares to the user for confirmation, then an EvidenceRecord onward.
    Why Muse
    Reading and classifying images is a vision job.
    Guard
    Health panels stop here with R1.
  3. 3

    Cite and profile

    Muse Spark 1.3 · high effort
    Gets
    The evidence, the citation index and the closest reference records.
    Does
    Interpretation picks sourced claims. The profiler writes plain-language cards for reference populations.
    Hands over
    Claims and profiles to the director.
    Why Muse
    Grounded explanation is language work that needs both the data and the sources in view.
    Guard
    Must use only supplied records and index entries.
  4. 4

    Director

    Muse Spark 1.3 · high effort
    Gets
    Evidence, claims, profiles, approved asset ids and any repair notes.
    Does
    Writes the full timed script.
    Hands over
    A ReelPlan draft to the auditors. On a rewrite it receives their merged issues.
    Why Muse
    Creative structure and wording under evidence constraints.
    Guard
    Schema-validated. Cannot approve itself.
  5. 5

    Two auditors

    Muse Spark 1.3 · high effort, two calls
    Gets
    The draft plan, in separate calls with separate instructions.
    Does
    One checks truth against the evidence, the other enforces the ancestry-only rules.
    Hands over
    Pass, revise or block with issues. Issues travel back to the director once. Both passing releases the plan to the image step (the amber arrow).
    Why Muse
    Judging meaning, not matching words.
    Guard
    A second failure ends the job with R4.
  6. 6

    Image agent

    Muse Image 1.0
    Gets
    Scene briefs built from cited records.
    Does
    Paints candidates, and applies a single targeted edit when told to.
    Hands over
    Each candidate picture to the visual auditor.
    Why Muse
    Visual reconstruction of a place and century.
    Guard
    Cannot approve its own candidate.
  7. 7

    Visual auditor

    Muse Spark 1.3 · medium effort
    Gets
    The actual image and the scene brief.
    Does
    Looks for anachronisms, text in frame, battle or political content, rendering defects and a cluttered caption area.
    Hands over
    Pass, repair (with an edit instruction) or fallback. A repair goes back to the image agent. A pass goes on.
    Why Muse
    Judging a picture is vision work, and a beautiful image can still be wrong.
    Guard
    One repair per scene and two per episode, then reviewed fallback.
  8. 8

    Assemble the film

    No model
    Gets
    The approved plan and approved images.
    Does
    Adds the deterministic globe scenes and plays the film from a clock.
    Hands over
    The finished episode to the page.
    Why no model
    The last step should only assemble what was approved.
    Guard
    No new claims after approval.
