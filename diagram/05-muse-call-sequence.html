What happens inside one Muse call

Every one of the agents in the other diagrams makes its calls this way. The model is treated as a capable but untrusted contractor: the adapter checks the budget before asking, reuses a saved answer when it can, forces the answer into a strict shape, and logs the cost afterward. Muse's own contribution is a single step in the middle. Everything around it is guard rails.

The critical view: what Muse is and is not trusted with

  • The model is the only part of the system that can return something unexpected. The adapter therefore treats its output as untrusted until it passes validation.
  • A saved answer costs nothing and returns instantly. That makes repeat runs and demos cheap and repeatable.
  • High effort is not free thinking. Spark counts its reasoning as output tokens, which is why the high tier has a 32,768 token ceiling and the cost log records every one.
  1. 1

    A stage asks

    Pipeline stage
    Gets
    Its own inputs.
    Does
    Calls the adapter with the agent name, model, effort, prompt, optional images, and the JSON schema and validator for the answer.
    Hands over
    The request to the adapter.
    Why no model
    Each stage describes what it needs and leaves the how to one shared module.
    Guard
    Prompts live in versioned files in the prompts folder.
  2. 2

    Kill switch and run cap

    No model
    Gets
    The request and the money already spent this run.
    Does
    Refuses immediately if paid calls are switched off, or if this call could push the run over $5.
    Hands over
    Either continues, or throws a typed error before any money moves.
    Why no model
    Cost safety must come before the call, not after.
    Guard
    The check happens first, so a runaway loop cannot spend.
  3. 3

    Cache key

    No model
    Gets
    The exact request.
    Does
    Fingerprints it with sha256 and looks in the local cache folder.
    Hands over
    A saved answer, or a miss.
    Why no model
    The same question should not be paid for twice.
    Guard
    Keys cover the model and the full prompt, so a changed prompt is a miss.
  4. 4

    Cache hit

    No model
    Gets
    A saved, already validated answer.
    Does
    Returns it with cost zero and marks the call as cached in the log.
    Hands over
    The typed result straight to the stage.
    Why no model
    Free, instant and identical on replay.
    Guard
    Only validated answers are ever saved.
  5. 5

    Ask Muse

    Muse Spark 1.3 (or Muse Image 1.0 for pictures)
    Gets
    The role instruction, the evidence or image, the response schema, and settings chosen by effort: low 0.2 and 1,024 tokens, medium 0.4 and 2,048, high 0.7 and 32,768.
    Does
    This is where the model reads, reasons and writes its structured answer. Pictures take a parallel route, priced at $0.01 per image.
    Hands over
    A raw completion back to the adapter.
    Why Muse
    This is the one step that needs intelligence. Matching effort to the task keeps simple calls cheap and gives hard ones room.
    Guard
    The schema is sent with the request so the model is asked for the right shape.
  6. 6

    Validate and retry once

    No model, then Muse once
    Gets
    The completion.
    Does
    Checks it against the Zod validator. If it fails, asks Muse again with the validation error attached so it can correct itself.
    Hands over
    A validated object, or a typed error after the second failure.
    Why no model
    Models sometimes return near-valid output. One informed retry fixes most of it, and a hard stop prevents loops.
    Guard
    Never rendered raw. Exactly one retry.
  7. 7

    Save and log

    No model
    Gets
    The validated answer and the usage figures.
    Does
    Writes the answer to the cache and appends a cost row: agent, model, effort, tokens, dollars, duration, status.
    Hands over
    The typed result to the stage.
    Why no model
    A real record of what each model call cost is how a run can be audited afterward.
    Guard
    Logs hold no prompts, pictures or personal data. The log is also what the exported evidence manifest reads.
