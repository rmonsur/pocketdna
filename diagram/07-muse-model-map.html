Which Muse model does which job, and why that setting

The adapter sits on top and sends each task to the cheapest setting that can do it well. Short decisions get the low tier. Reading digits gets the medium tier. Work that has to hold many rules at once gets the high tier. Muse Image draws. Wonder and Muse Code helped build the project but are not in the runtime path.

The critical view: what Muse is and is not trusted with

  • Muse never computes ancestry. The percentages come from deterministic math in your browser, or from the numbers you confirmed on a screenshot.
  • Muse never approves its own work. Whoever writes is never the one who checks, and every check is a separate call with a separate instruction.
  • Muse never decides geography. Map points come from dated records in a reference table, so a model cannot invent a route.
  • Everything Muse returns must fit a strict schema and is validated by code. Output that does not fit is retried once, then becomes a typed error. It is never shown raw.
  • Why Spark for everything in text: one model family means one adapter, one set of schemas and one cost model. The separation between writer and judge comes from separate calls and instructions, not from different models.
  • Honest scope: this build calls Meta's hosted API. It does not run the open-weight Glimmer or Spark Open models.
  1. 1

    Muse adapter

    Server only
    Gets
    Every request from the pipeline.
    Does
    Chooses the model and the effort settings, applies the guards, and logs cost.
    Hands over
    Typed results.
    Why no model
    One gate for money, caching and validation.
    Guard
    Kill switch, $5 cap, sha256 cache, schema plus Zod, one retry, cost log.
  2. 2

    Low effort

    Muse Spark 1.3 · temperature 0.2 · 1,024 tokens
    Gets
    A screenshot.
    Does
    Gatekeeper: names the vendor, spots health panels and decides accept or reject.
    Hands over
    A tiny verdict.
    Why Muse
    A short, clear decision. More thinking would only add cost.
    Guard
    Rejects health data before anything else runs.
  3. 3

    Medium effort

    Muse Spark 1.3 · temperature 0.4 · 2,048 tokens
    Gets
    A screenshot or a generated picture.
    Does
    Extractor reads percentages. Visual auditor inspects generated images.
    Hands over
    Typed shares, or a pass, repair or fallback verdict.
    Why Muse
    Careful perception with a bounded answer. Accuracy matters more than reasoning depth.
    Guard
    A person confirms extracted numbers. The generator never audits its own picture.
  4. 4

    High effort

    Muse Spark 1.3 · temperature 0.7 · 32,768 tokens
    Gets
    Evidence, claims, profiles or a whole plan.
    Does
    Interpretation, population profiler, director, narrative auditor and compliance auditor.
    Hands over
    Cited claims, profiles, the timed script and the two audit verdicts.
    Why Muse
    These tasks hold many constraints at once and need room to reason. Spark counts its reasoning as output, hence the large ceiling.
    Guard
    Writers and judges are separate calls. One repair, then stop.
  5. 5

    Muse Image

    Muse Image 1.0
    Gets
    Scene prompts from cited records.
    Does
    Paints up to six 16:9 scenes, two at a time, and applies a single edit when an audit asks for one.
    Hands over
    Picture files to the audit.
    Why Muse
    Visual reconstruction at $0.01 per image.
    Guard
    Fictional inhabitants only. Cannot approve its own work.
  6. 6

    Muse Wonder

    Development only
    Gets
    Builder questions and scripts.
    Does
    Helped with research, diagnostics and documentation while building.
    Hands over
    Nothing at runtime.
    Why no model
    A heavier model for the hardest build-time tasks, kept out of the user's path so judges need no extra access.
    Guard
    Not a runtime dependency.
  7. 7

    Muse Code

    Built the codebase
    Gets
    The builder's specifications.
    Does
    Wrote the repository during the hackathon, including the browser ancestry engine, under review and tests.
    Hands over
    The source code.
    Why no model
    A coding model implemented a hard bioinformatics method and was checked against the Reich Lab's smartpca.
    Guard
    Numerical parity fixtures and an offline test suite.
